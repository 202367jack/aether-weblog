# 在新服务器上部署这个博客

前提：服务器已经按 [cloud-server-setup](https://github.com/202367jack/cloud-server-setup) 跑完环境准备（Ubuntu 24.04、Docker、基础工具、swap、时区），安全组放行 **22 / 80 / 443**。

整条链路只有四步：装 Nginx → 配部署密钥 → 配 GitHub Secrets → push。

---

## 1. 装 Nginx 并建站点

```bash
# 1. 建目录（第一次登录的新机器上没有 /dev-ops）
mkdir -p /dev-ops

# 2. 拉代码
git clone git@github.com:202367jack/aether-weblog.git /dev-ops/aether-weblog
cd /dev-ops/aether-weblog

# 3. 装 Nginx 并建站点
sudo bash scripts/install-nginx.sh
```

脚本做的事（幂等，可重复执行）：

| 步骤 | 内容 |
|---|---|
| 依赖 | `build-essential libpcre2-dev zlib1g-dev libssl-dev curl` |
| 编译 | 默认 1.30.6，源码来自 nginx.org，装到 `/codedeveloper/circumstances/nginx/nginx-<版本>` |
| 软链 | `current -> nginx-<版本>`，升级只要重跑脚本 |
| 配置 | 写 `conf/nginx.conf` 与 `conf/sites/blog.conf`（已存在则跳过） |
| 站点目录 | `/var/www/blog`，属主 `www-data` |
| 服务 | 写 `/etc/systemd/system/nginx-cloud.service`，`enable --now` |

预期输出末尾：

```
版本：nginx version: nginx/1.30.6
端口：0.0.0.0:80,[::]:80
本机访问：200
```

自定义参数：

```bash
sudo NGINX_VERSION=1.30.6 WEB_ROOT=/var/www/blog SERVER_NAME=_ bash scripts/install-nginx.sh
```

## 2. 配部署密钥（Actions 用）

在**本地**生成一把专用密钥（不要用你个人那把）：

```powershell
ssh-keygen -t ed25519 -C "github-actions-blog" -f $env:USERPROFILE\.ssh\blog_deploy -N '""'
```

把公钥追加到服务器：

```powershell
type $env:USERPROFILE\.ssh\blog_deploy.pub | ssh root@<服务器IP> "cat >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys"
```

验证免密：

```powershell
ssh -i $env:USERPROFILE\.ssh\blog_deploy root@<服务器IP> "echo 免密登录成功"
```

## 3. 配 GitHub Secrets

仓库 → Settings → Secrets and variables → Actions → New repository secret，三个：

| Name | Value |
|---|---|
| `SERVER_HOST` | 服务器公网 IP |
| `SERVER_USER` | `root` |
| `SSH_PRIVATE_KEY` | `blog_deploy` 私钥全文（含 BEGIN/END 两行） |

私钥在本地查看：

```powershell
Get-Content "$env:USERPROFILE\.ssh\blog_deploy" -Raw | Set-Clipboard
```

## 4. 首次部署

任选其一：

**A. 让 Actions 跑**：随便改一行 push 上去，或到 Actions 页点 `Run workflow`。

```bash
git commit --allow-empty -m "chore: 触发首次部署"
git push
```

**B. 本地手动推一次**（不依赖 Actions，适合排错）：

```powershell
hugo --minify --gc
scp -i $env:USERPROFILE\.ssh\blog_deploy -r public/* root@<服务器IP>:/var/www/blog/
```

验证：

```bash
curl -I http://<服务器IP>/
# 期望 HTTP/1.1 200 OK
```

## 换域名 / 开 HTTPS（域名备案通过后）

```bash
# 1. 改站点 server_name
sudo sed -i 's/server_name _;/server_name aether.example.com;/' \
  /codedeveloper/circumstances/nginx/current/conf/sites/blog.conf

# 2. 同步 hugo.toml 的 baseURL，然后
sudo /codedeveloper/circumstances/nginx/current/sbin/nginx -t && \
sudo systemctl reload nginx-cloud

# 3. 签证书（webroot 模式，已有的 acme-challenge 位置就是给它用的）
sudo apt install -y certbot
sudo certbot certonly --webroot -w /var/www/blog -d aether.example.com
```

拿到证书后把 `listen 80` 的 server 块复制一份改成 `listen 443 ssl`，加上：

```nginx
ssl_certificate     /etc/letsencrypt/live/aether.example.com/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/aether.example.com/privkey.pem;
ssl_protocols TLSv1.2 TLSv1.3;
```

80 那边加 `return 301 https://$host$request_uri;`。续期由 `certbot renew` 的 systemd timer 负责，reload 挂个 hook：

```bash
echo -e '#!/bin/sh\nsystemctl reload nginx-cloud' | sudo tee /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
sudo chmod +x /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
```

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `403 Forbidden` | `/var/www/blog` 权限或属主不对 | `chown -R www-data:www-data /var/www/blog` |
| `404` 但文件存在 | 站点 root 写错 | 看 `conf/sites/blog.conf` 的 `root` |
| 改了配置不生效 | 没 reload | `sudo systemctl reload nginx-cloud` |
| `nginx: [emerg] unknown directive` | 配置语法错 | `sudo .../sbin/nginx -t` 看行号 |
| Actions 报 `Permission denied (publickey)` | 私钥贴错或公钥没进 `authorized_keys` | 本地 `ssh -i` 先验证 |
| Actions 报 `rsync: command not found` | 服务器缺 rsync | `sudo apt install -y rsync` |
| 页面是旧的 | HTML 被缓存 | 强制刷新；确认部署时 `--delete` 生效 |
| 图片 404 | 图片没跟着 push，或文件名带中文空格 | 图片放文章同目录，用英文名 |
